<objective>
Introduce client-side routing (`react-router-dom`) and land the first end-to-end, production-quality slice of the trip-detail page: a participant can click a trip in the trip list, land on `/trips/:tripId`, and see that trip's name and items loaded from Phase 6's single-query `GET /trips/:tripId` snapshot — with correct loading and "not found" states.

This plan satisfies TRIP-01 in full. It deliberately does NOT build the inline-edit table (add/edit/delete) — that is Plan 08-02's job, which depends on the routing/fetch scaffolding this plan lands.

Purpose: Prove the routing + data-fetch architecture end-to-end (tracer-first) before building out the heavier, stateful inline-edit interactions on top of it.
Output: `react-router-dom` installed and wired; `TripDetail.tsx` page component; `getTripDetail` API client function; trip-list navigation.
</objective>
