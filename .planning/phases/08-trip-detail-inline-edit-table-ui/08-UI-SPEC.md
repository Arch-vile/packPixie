> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — `components.json` not present; codebase has an established hand-rolled CSS pattern (`App.css`) with occasional raw Tailwind utility classes (`Header.tsx`). Introducing shadcn mid-milestone for one table phase would be an unplanned refactor with no upstream decision backing it — declined. Revisit at a future milestone boundary if the UI surface grows enough to justify it. |
| Preset | not applicable |
| Component library | none — native HTML (`<table>`, `<input>`, `<select>`, `<button>`) styled with custom CSS classes, following the existing BEM-lite naming already used in `App.css` (`.trip-list`, `.trip-item`, `.btn-primary`). New classes for this phase should follow the same convention, e.g. `.item-table`, `.item-row`, `.cell-status`. Tailwind utility classes remain permissible for one-off layout tweaks (precedent: `Header.tsx`'s `w-full bg-black`), but the token values below (spacing/type/color) are the source of truth regardless of authoring method. |
| Icon library | none — reuse plain-character glyphs already established in `TripList.tsx` (e.g. `×` for tag removal). Do not add a new icon dependency for this phase; there is no existing icon usage to be consistent with, and the interaction surface (buttons, selects, checkboxes) doesn't require icons to be legible. |
| Font | `system-ui, Avenir, Helvetica, Arial, sans-serif` — already declared in `index.css` `:root`, inherited automatically, no new font work needed. |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/glyph gaps, inline padding inside compact controls (checkbox label gap) |
| sm | 8px | Compact element spacing (cell internal padding, gap between inline row controls) |
| md | 16px | Default element spacing (form field stacking, section margins) |
| lg | 24px | Section padding (page container top/bottom padding, spacing between page header and table) |
| xl | 32px | Layout gaps (rare this phase — reserve for major page-region separation if needed) |
| 2xl | 48px | Major section breaks (not expected to be used this phase — single-page table view) |
| 3xl | 64px | Page-level spacing (not expected to be used this phase) |

Exceptions: The existing global button/input rules in `index.css`/`App.css` use non-4px-multiple values (`0.4rem`/`0.6em` ≈ 6.4px/9.6px padding) — this is pre-existing tech debt on shared/global selectors (`button`, `.sign-out-btn`) and must **not** be propagated into new Phase 8 classes. All new `.item-table`/`.item-row`/`.trip-detail-*` classes must use the 4px-multiple scale above. One exception is permitted: icon-only controls (if any delete/remove buttons end up icon-only rather than labeled) get a 44px minimum touch target per accessibility convention, overriding the visual box size.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 13px | 500 | 1.3 |
| Heading | 20px | 500 | 1.2 |
| Display | n/a — not used this phase | — | — |

Notes:
- Body (16px/400/1.5) is the existing `:root` default in `index.css` — applies to table cell text, inputs, selects, buttons, form copy.
- Label (13px/500/1.3) matches the existing `.85rem`/`.8rem` meta-text pattern (`trip-date`, `participant-label`) — use for column headers, helper text, and inline error/conflict messages.
- Heading (20px/500/1.2) is for the trip-detail page title (trip name) — matches the existing `1.2rem` used in `.trip-list-header h2`.
- Only two weights are used project-wide: 400 (regular, body text) and 500 (the existing "semibold" — used for buttons, `.trip-name`, headings). Do not introduce 600/700 — stay consistent with what's already established.
- Display size intentionally unused — this phase has no hero/marketing text; the app-level `<h1>PackPixie</h1>` (51px) is out of this phase's scope and untouched.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` | Page background, table background, input/select backgrounds |
| Secondary (30%) | `#fafafa` (fill) / `#ddd` (1px border, 8px radius) | Add-item form container, table header row background, disabled-row background |
| Accent (10%) | `#4a90d9` (hover `#357abd`) | Reserved for: the "+ Add item" primary CTA button, the "Refresh" action button inside the 409-conflict banner. Nothing else — not links, not focus rings (browser default focus outline is used for inputs/selects, not accent color). |
| Destructive | `#cc0000` | Delete button, delete-confirmation copy, mutation-failure and 409-conflict inline error text |

Accent reserved for: "+ Add item" button, "Refresh" button in the conflict-recovery banner. All other buttons (Cancel, secondary actions) use the existing `.btn-secondary` neutral style (`#fff` bg, `#ccc` border, `#333` text).

These values are lifted directly from the existing `.btn-primary`/`.btn-secondary`/`.error-message`/`.create-trip-form` rules in `App.css` — no new palette introduced, for visual continuity with `TripList.tsx`.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "+ Add item" — appends a new row (defaults: `PackedBy` = current user, `Status` = unset per ITEM-01) at the bottom of the table, immediately editable. Mirrors the existing "+ New Trip" pattern in `TripList.tsx`; chosen over a persistent always-present blank row because a discoverable button is clearer once the table already has rows, and matches the one established precedent in this codebase. |
| Empty state heading | (none — a table has no heading slot; the empty state replaces the table body directly) |
| Empty state body | "No items yet. Add one to get started!" — mirrors the existing `.empty-state` copy pattern in `TripList.tsx` ("No trips yet. Create one to get started!") |
| Error state (mutation failure, non-409) | "Failed to save changes. Please try again." — rendered inline beneath the affected row; the optimistic value is rolled back to the last known-good server value first (per D-03) |
| Error state (409 conflict) | "Item was modified concurrently — refresh and retry." (verbatim server message, Phase 7) — rendered inline on the affected row alongside a "Refresh" button that re-fetches the full trip-detail snapshot (`GET /trips/:tripId`). No blind auto-retry. |
| Error state (trip fetch failure / not found) | "Trip not found." with a "Back to my trips" link to `/`. Identical copy for a non-member and a genuinely unknown `tripId` — never reveal which (Phase 6 D-02, 404-not-403 contract) |
| Loading state | "Loading trip…" — replaces the table area while the initial `GET /trips/:tripId` is in flight |
| Destructive confirmation | Delete row: native `confirm()` dialog — `Delete "{item name}"? This can't be undone.` Chosen over a custom modal because the codebase has zero existing dialog/modal primitives; introducing one for a single confirmation is disproportionate, and ITEM-03 only requires *a* confirmation, not a specific style. |
| Disabled-control tooltip | Delete button on a `packed` row: disabled, with `title="Unpack item before deleting"` — pre-emptively prevents the wasted round-trip Phase 7 D-09 would otherwise reject with a 400 |

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5) and lifted by plan-phase's
> `## UI Considerations` lift rule via the identical rule as SPEC `## Edge Coverage`. Shape-rooted UI *state*
> coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text).
> Empty-state and error-state COPY live in `## Copywriting Contract` above — this section covers
> state coverage and REFERENCES those rows rather than restating the copy (de-dup).

Applicable state considerations resolved: 12 covered, 3 backstop, 0 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | item table | ✅ covered | `items.length === 0` renders the "Empty state" row's copy in place of the table body |
| loading | trip-detail page | ✅ covered | "Loading trip…" copy (see Copywriting Contract) renders while the initial `GET /trips/:tripId` is in flight, replacing the table area |
| error (fetch) | trip-detail page | ✅ covered | Non-200/network failure on initial load renders the "Trip not found." copy (same for non-member and unknown trip, per Phase 6 D-02) with a link back to the trip list |
| error (mutation, non-409) | item row | ✅ covered | Failed `PATCH`/`POST`/`DELETE` rolls back the optimistic value and renders the "Failed to save changes" copy inline beneath the row |
| error (409 conflict) | item row | ✅ covered | Rolls back the optimistic value, renders the verbatim server message + a "Refresh" button (see Copywriting Contract) rather than auto-retrying |
| populated | item table | ✅ covered | Standard row rendering against the `Item` shape — one `<tr>` per item, one `<td>` per field |
| partial | Weight cell | ✅ covered | Empty input renders blank (`undefined`/absent), distinct from a typed `0`, matching ITEM-06/D-06's absent-vs-zero rule |
| partial | Name cell (blank-guard) | ✅ covered | Trimmed-empty `Name` blocks the auto-save `PATCH` client-side and shows a red-outline visual flag (D-07) — the row is visibly "invalid" without a separate error-copy row (the visual flag itself is the signal) |
| zero-one-many | PackedBy select | ✅ covered | Options are always `trip.participants` + an "Unassigned" option — works identically for 1 participant or N |
| zero-one-many | Add-item CTA | ✅ covered | "+ Add item" behaves identically whether the table currently has 0 rows (replacing the empty state) or N rows (appending) |
| disabled state | Delete control, packed row | ✅ covered | Disabled + tooltip (see Copywriting Contract), avoiding the Phase 7 D-09 400 round-trip |
| navigation | Trip list → trip detail | ✅ covered | The entire `.trip-item` card becomes a `<Link to={`/trips/${tripId}`}>` wrapper (whole-row-click), with `cursor: pointer` and the existing hover treatment — chosen over a dedicated "Open" link/button to keep the existing card markup/visual weight unchanged |
| overflow | Name cell, long item name | 🧪 backstop | The cell is a live `<input>`, not static text — it scrolls horizontally within a fixed-width column rather than truncating; verify column width doesn't visually break the row grid at very long names |
| overflow | PackedBy select, long email | 🧪 backstop | Native `<select>` truncation is browser-default; no custom handling planned — verify it doesn't visually break at long email addresses |
| long-text | Category free-text cell | 🧪 backstop | No client-side max-length enforced (matches existing no-client-validation precedent beyond the Name blank-guard) — verify a very long category string doesn't break the row layout |
